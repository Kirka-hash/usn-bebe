# Бриф для фронтенда (можно целиком вставить в нейросеть)

> Скопируй этот файл в промпт и добавь: «Сделай фронтенд по этому брифу в папке `frontend/` репозитория usn-bebe».

## Что делаем
Веб-сервис для соревнований по управленческой борьбе (заказчик — Универсальная школа переговоров, USN).
Две части:
- **участник** (игрок, судья, секундант, зритель) регистрируется на турнир — **мобильная** вёрстка (390 px), но должна работать и на десктопе;
- **организатор** смотрит заявки, доступность судей и коллегии, которые предлагает ИИ — **десктоп** (1280 px).

Язык интерфейса — русский. Фирменный стиль — по макетам Figma «USN_design».

## Стек и правила (обязательно)
- **React + Vite + TypeScript**, роутинг — `react-router`. Стили — на выбор (Tailwind или CSS-модули), главное — как в макетах.
- Код лежит в **`frontend/`** репозитория `github.com/Kirka-hash/usn-bebe`.
- **Фронтенд ходит ТОЛЬКО в наш бэкенд** (`http://localhost:8000/api`). Напрямую в API USN (devcompetition.usnexpert.com) **не обращаться**: туда ходит бэкенд, там пароль, и его нельзя светить в браузере.
- Адрес бэкенда — из переменной `VITE_API_URL` (по умолчанию `http://localhost:8000/api`).
- **Никаких паролей и ключей в коде.**
- Работа в ветке `sprint3/frontend-…`, в `main` — через Pull Request.
- **Бизнес-правила проверяет бэкенд.** Фронтенд показывает его ответ: ошибка приходит как `422 {"detail": {"code": "...", "message": "..."}}` — выводить `message` пользователю.

## Как запустить бэкенд (уже работает на тестовых данных)
```bash
pip install -r requirements.txt
uvicorn backend.main:app --reload
```
Все методы с примерами — http://localhost:8000/docs (там же можно потыкать).
Демо-соревнования: `cup-challenge-classic` (классика), `cup-coop-team` (командный), `cup-strategy-express` (экспресс, игроки закрыты).

## Методы нашего API
| Метод | Для какого экрана |
|---|---|
| `POST /auth/request-code {email}` → письмо с кодом (пока код пишется в лог сервера) | U2 |
| `POST /auth/verify {email, code}` → `{token}` | U2 |
| `GET /competitions` — турниры с открытыми ролями | U1 |
| `GET /competitions/{id}` — карточка: формат, роли, сроки, блоки судей | U3, U6c |
| `GET /competitions/{id}/roles?user_id=` — `{player: null \| "причина", ...}` (null = доступна) | U4 |
| `POST /applications` — создать или обновить заявку (повтор — не дубль) | U7 |
| `GET /users/{user_id}/applications` — мои заявки | U8, U9 |
| `GET /competitions/{id}/team-invitations?user_id=` — кто пригласил меня в команду | U8b, U9 |
| `POST /competitions/{id}/team/confirm` и `/team/decline` `{user_id, inviter_id}` | U8b |
| `GET /organizer/competitions/{id}/applications` | O2 |
| `POST /organizer/applications/{id}/status?status=confirmed\|rejected` | O2 |
| `GET /organizer/competitions/{id}/availability?panel_size=9&reserve=3` — карта доступности | O3 |
| `POST /organizer/panel-proposal` — предложение коллегий + объяснение + варианты при нехватке | O4, O5 |

Тело заявки (`POST /applications`):
```json
{
  "competition_id": "cup-coop-team",
  "role": "player",                     // player | voter | adviser | viewer
  "profile": {"user_id": "u1", "email": "a@b.ru", "last_name": "Иванов", "first_name": "Пётр",
              "country": "Россия", "city": "Екатеринбург", "club": "", "position": "", "company": "",
              "intro": "", "telegram": "", "vk": ""},
  "partner_user_id": "u2",              // только игрок в командном турнире
  "advised_player_ids": [],             // только секундант (можно несколько)
  "availability_block_ids": [],         // только судья (минимум один)
  "consents": {"rules": true, "pd": true, "media": true}
}
```

## Экраны участника (мобайл)
| ID | Экран | Что на нём | Кнопки → куда |
|---|---|---|---|
| U1 | Турниры | карточки: название, формат, даты, открытые роли (до какого числа) | «Подробнее» → U3; «Войти» → U2 |
| U2 | Вход | email → код из письма → вход. Новый пользователь: Фамилия, Имя | «Продолжить» → U3 (откуда пришёл); «Заполнить профиль» → U2a |
| U2a | Профиль | Фамилия*, Имя*, Страна*, Город*, Телефон, Школа/клуб, Должность, Компания, Как представить, Telegram, VK | «Сохранить» → U3 |
| U3 | Карточка турнира | формат, даты, роли и сроки | заявки нет: «Зарегистрироваться» → U4; есть: «Моя заявка» → U8 |
| U4 | Выбор роли | 4 роли; недоступные — серые с причиной (из `/roles`) | Игрок: командный турнир → U6a, иначе → U5. Секундант → U6b. Судья → U6c. Зритель → U5. **Формат (командный или нет) берём из турнира — пользователь его не выбирает** |
| U6a | Напарник (только командный) | поиск напарника среди игроков USN; если меня уже пригласили — пригласивший подставлен | «Далее» → U5; «Назад» → U4 |
| U6b | Кому секундирую (только классика) | выбор одного или нескольких игроков турнира, себя выбрать нельзя | «Далее» → U5 |
| U6c | Судья: доступность | чекбоксы блоков времени (минимум один); коллегию не выбирает | «Далее» → U5 |
| U5 | Анкета | поля из профиля (подставлены), обязательные: Фамилия, Имя, Страна, Город | **одна кнопка** «Далее» → U7; «Назад» → U4 |
| U7 | Согласия и отправка | 3 чекбокса: правила, ПДн, фото/видео | «Отправить» → U8; ошибка → текст ошибки, данные не теряются |
| U8 | Моя заявка | статус: Получена / Подтверждена / Отклонена; для команды — «Ждёт подтверждения напарника» / «Команда подтверждена» / «Напарник отклонил» | «Редактировать» → U5 (если роль открыта); «Сменить напарника» → U6a; «+ Стать секундантом» → U6b (игрок в классике); «Отозвать»; «Мои турниры» → U9 |
| U8b | Приглашение в команду | «Иванов указал вас напарником» | «Подтвердить» → U8; «Отклонить» → U9; «Я ещё не зарегистрирован» → U4 |
| U9 | Мои турниры | заявки по турнирам + карточки приглашений | «Открыть» → U8 / U8b |

## Экраны организатора (десктоп, общая шапка с вкладками)
Вкладки на O2–O5: **Заявки · Доступность судей · Коллегии (ИИ) · Проблемные поединки (ИИ)**.

| ID | Экран | Что на нём | Действия |
|---|---|---|---|
| O1 | Соревнования | таблица турниров: формат, даты, открытые роли, сколько заявок | «Открыть» → O2. Создание турниров — в Django Admin заказчика, **не делаем** |
| O2 | Заявки | таблица: участник, роль, связи (секундант → игроки, напарник, статус команды), статус; фильтры по роли и статусу | «Подтвердить» / «Отклонить», «Карточка» → O2a. **Резерва нет** |
| O2a | Карточка участника | данные, для судьи — доступность и баллы экспертов 1–3 по коллегиям | статус; «← К заявкам» |
| O3 | Карта доступности | судьи × блоки времени, внизу «доступно / нужно» (зелёный / жёлтый / красный) | «Сформировать коллегии» → O4; «Разобрать дефицит» → O5 |
| O4 | Коллегии — предложение ИИ | поединки × коллегии (Нанимающиеся / Отправляющие / Доверяющие / Резерв), у судьи — балл; состав по регламенту (не меняется) | «Почему так?» → объяснение; «Пересчитать»; «Утвердить». ИИ **не назначает сам** |
| O5 | Проблемные поединки | список с причиной + варианты: А) судьи соседнего блока, Б) пригласить опытных, В) резервный судья за недостающую коллегию; текст приглашения | «Применить вариант» → O4; «Скопировать текст» |

## Порядок работы (предложение)
1. Каркас: Vite + роутинг + шапка + вызов `GET /competitions` → U1 показывает демо-турниры.
2. Сценарий участника U1 → U3 → U4 → U5/U6 → U7 → U8 (главный E2E для демо).
3. Кабинет организатора O2 → O3 → O4 (приоритет заказчика — организатор).
4. U8b/U9 (команды), O5.
