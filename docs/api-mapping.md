# Сверка API USN (dev-стенд) с нашими сценариями

Проверено 17.11.2026 на `https://devcompetition.usnexpert.com/api` (Swagger 2.0, Basic Auth / сессия).
Методы проверялись **вызовами** (только чтение — GET; POST/PUT не вызывали, чтобы не менять общие данные стенда).

## Что есть в API (14 методов, без `cases` и `tags`)

| Метод | Что делает | Проверка вызовом |
|---|---|---|
| `GET /competitions/` | список соревнований: тип (`classic`/`quick`/`team`), флаги открытия ролей `player/voter/viewer/adviser_entry_open`, дни, игроки | ✅ 6 соревнований |
| `GET /competitions/{id}/` | расписание по дням: игры (поединки) со временем, игроками, судьями с коллегией (`voter_type`: `employee` / `negotiator` / `founder`) и резервом | ✅ у «Кубок Вызова 2025, КУБ» 44 пункта, 28 игр |
| `GET /time-slots/?competition_id=` | слоты доступности судей: день, начало/конец, `max_voters`, `assigned`, `available` | ⚠️ работает, но у всех 6 соревнований — **0 слотов** |
| `POST /applications/` | заявка: `user_id`, `competition_id`, `role`, `time_slot_id`; 409 — уже есть заявка на это соревнование и роль; 422 — роль закрыта и т. п. | не вызывали |
| `GET /applications/list/?user_id=&competition_id=` | заявки со статусом `pending / approved / rejected` | ✅ работает, заявок пока 0 |
| `POST /users/` · `PUT /users/{id}/` | создать / обновить профиль участника | не вызывали |
| `GET /users/by-email/{email}/` | найти участника по email (профиль + рейтинги + заявки) | метод есть (добавлен 16.11) |
| `GET /users/by-telegram/{id}/` | найти по Telegram ID | метод есть |

## Что заметили в данных стенда
- У соревнований типа `quick` и `team` открыта роль **секунданта** (`adviser_entry_open: true`), хотя по правилам секундант бывает только в классике. Наш сервис такую заявку не пропустит, но стоит поправить настройку на стенде.
- Ни у одного соревнования нет слотов судей (`requires_time_slots: false`). Для теста нужен турнир со слотами.
- В ответе `/competitions/` полные имена игроков, а в `/users/by-email/` — полный профиль. В LLM передаём только обезличенные ID (ADR-0003).

## Что попросить у заказчика (по приоритету)

1. **Несколько слотов в заявке судьи** — `time_slot_ids: [..]` вместо одного `time_slot_id`. *Задача:* судья отмечает все блоки, когда может судить (U6c), а организатор видит карту доступности (O3).
2. **Редактирование и отзыв заявки** — `PATCH /applications/{id}/`, `DELETE` или статус `withdrawn`. *Задача:* по ответу заказчика 10.11 заявку можно править после «Получена» (U8).
3. **Смена статуса заявки** — `PATCH /applications/{id}/status` (`approved` / `rejected`). *Задача:* организатор подтверждает заявки в одном месте (O2). Если это остаётся в Django Admin — скажите, мы уберём кнопки.
4. **Связи в заявке** — `advised_player_ids` для секунданта (несколько игроков) и `partner_user_id` для командного формата. *Задача:* U6a, U6b и подбор коллегий без конфликтов интересов.
5. **Поиск пользователей** — например, `GET /users/?role=player&search=Иванов`. *Задача:* напарник выбирается из всех игроков USN (ответ заказчика 10.11).
6. **Согласия в заявке** — `consent_rules`, `consent_pd`, `consent_media`. *Задача:* по правилам заявка = согласие (U7).
7. **Сохранение распределения судей по играм** — `PUT /games/{id}/judges` с коллегией и резервом. *Задача:* утверждённое ИИ-распределение (O4) попадает в систему USN. Если судей в игры вносят только в Admin — подтвердите.
8. **Даты закрытия регистрации по ролям** в `/competitions/` (желательно). *Задача:* показать «регистрация до 19.03» (U3).
9. **Оценки судей 1–3 по коллегиям** — поле в профиле или отдельный метод (можно позже). Пока берём из Excel.
10. **Уточнить обязательность полей профиля:** в API обязательны телефон и клуб, страна — нет; в ТЗ — наоборот.
