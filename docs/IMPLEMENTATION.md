- Playwright `org-check.js` — организаторский MVP: гвард без входа, неверные/пустые данные, вход демо-аккаунтом, валидация формы, создание, дубликат названия, персистентность после reload, видимость турнира участнику, блокировка роли судьи у нового турнира, выход — ALL CLEAN.

## Чистка прототипных артефактов

- Коды экранов (U2, O2a…) убраны из шапок: `ScreenHeader` рендерит только заголовок и опциональную подпись.
- Жёлтые заметки-инструкции реализованы как поведение и нигде не отображаются; в исходниках остались только комментарии разработчика с кодами экранов (не UI).
- Все инпуты стартуют пустыми с осмысленными placeholder («например: Кубок Весны 2026 · Классика», «18–19.04», «онлайн (Zoom)…»).
- Демо-данные (судьи, коллегии, разборы поединков) скоуплены на «Кубок Вызова 2026» как демо-контент информационных экранов; созданные организатором турниры показывают честные пустые состояния («…ещё нет», «слоты не открыты»).
- Статичный демо-баннер O2 заменён реакцией на подтверждение судьи организатором.

## Кабинет организатора (MVP)

1. Вход `/organizer/login` — демо-аккаунт `organizer@usn.demo` / `organizer` (не production-аутентификация, показан на экране явно; реальный вход — на backend).
2. Дашборд `/organizer` — список всех турниров (демо-сид + созданные), кнопки «Создать турнир» и «Выйти из кабинета».
3. Создание `/organizer/competitions/new` — форма с валидацией (название ≥3, описание ≥10, формат дат, уникальность), сохранение в демо-БД (localStorage `usn.demo.v1`), персистентно между перезагрузками.
4. Созданный турнир виден участникам (U1/U3), в нём работают все участнические потоки; судейские слоты не заданы → регистрация судей закрыта («Судейские слоты ещё не открыты», правило №3); секундант есть только в классике.

## Зафиксированные решения и неопределённости

### Зафиксировано (решение реализации)

1. **Метод объединения баллов ОС/КС** — среднее арифметическое пары; отображение целое или с запятой («2,5»). Файл `src/utils/judges.ts` (`avgScore`, `pairLabel`), применяется одинаково в O4/O4a.
2. **Гейтинг судейских слотов** — `resolveRoleBlockReason` возвращает «Судейские слоты ещё не открыты», `submitApplication` бросает `ApiError('no-slots', …)`; UI U4/U6c/U7 отражает правило.
3. **Формат игрока** — берётся из `tournament.format`, а не из выбора пользователя (U4 → U5 или U6a).
4. **Краткие имена в связях O2** — «Петров И.», определение по первому слову [ESTIMATED — в прототипе просто пример].
5. **Группировка U9** — заявки одного турнира в одну карточку, статус карточки = лучший из статусов (confirmed > received) [ESTIMATED].
6. **Статус после редактирования** — остаётся прежним; изменений статуса нет до решения заказчика.

### [UNKNOWN] — не реализовано, не выдумано

1. Подтверждение команды вторым игроком (U6a) — «ждём решения заказчика».
2. Поведение статуса заявки после редактирования — сохраняем как есть; финализирует бэкенд USN.
3. Управление отклонёнными/[резервом] — вне MVP, организатор ведёт в Telegram (UI убран).

### Осознанные добавления сверх прототипа

1. **Глобальная шапка сайта** (`SiteLayout`) — навигация между разделами; в прототипе переходы — стрелки Present-режима.
2. **«Скрыть» у warn-баннера O2** — баннер прототипа статичен; добавлен dismiss для usable-состояния.

## Что требует backend

- Реальные API USN (соревнования, заявки, блоки доступности из Django Admin), ошибка «Судейские слоты ещё не открыты» (409/422) при открытии регистрации судей без слотов.
- Production-аутентификация организатора (сейчас — демо-аккаунт, проверка локальная) и Google OAuth/email-коды для участников.
- Сохранение созданных организатором турниров на сервере (сейчас — демо-БД в localStorage).
- Подтверждение статуса «Получена» от API USN (статус ставится только после подтверждения сохранения) — в моке статус ставится сразу.
- Пересчёт коллегий — локальная симуляция задержки; реальный пересчёт и LLM-объяснения — на бэкенде.
- Отправка приглашений судьям (текст готов, отправка вручную).
